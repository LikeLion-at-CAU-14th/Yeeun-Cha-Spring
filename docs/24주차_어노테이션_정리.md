# 24주차 Spring CRUD 주요 어노테이션 정리

## 1. Spring Web 어노테이션

### `@RestController`

클래스를 HTTP 요청을 처리하는 컨트롤러로 등록한다. 메서드의 반환값은 JSON과 같은 HTTP 응답 Body로 전달된다.

```java
@RestController
public class OrderController {
}
```

이번 과제에서는 `OrderController`가 주문 생성, 조회, 수정, 삭제 요청을 받도록 사용했다.

---

### `@RequestMapping`

컨트롤러에서 공통으로 사용할 URL 경로를 지정한다.

```java
@RequestMapping("/orders")
```

이후 각 메서드에 작성하는 주소는 `/orders` 뒤에 연결된다.

```text
GET /orders/1
PUT /orders/1
DELETE /orders/1
```

---

### `@PostMapping`

HTTP POST 요청을 특정 메서드와 연결한다. 새로운 데이터를 생성할 때 주로 사용한다.

```java
@PostMapping
public ResponseEntity<OrderResponseDto> createOrder(...) {
}
```

이번 과제에서는 `POST /orders` 요청으로 주문을 생성했다.

---

### `@GetMapping`

HTTP GET 요청을 특정 메서드와 연결한다. 데이터를 조회할 때 사용한다.

```java
@GetMapping("/{orderId}")
```

```java
@GetMapping("/buyer/{buyerId}")
```

이번 과제에서는 주문 단건 조회와 구매자별 주문 목록 조회에 사용했다.

---

### `@PutMapping`

HTTP PUT 요청을 특정 메서드와 연결한다. 기존 데이터를 수정할 때 사용한다.

```java
@PutMapping("/{orderId}")
```

이번 과제에서는 배송 상태가 `PREPARATION`인 주문의 배송정보를 수정할 때 사용했다.

---

### `@DeleteMapping`

HTTP DELETE 요청을 특정 메서드와 연결한다.

```java
@DeleteMapping("/{orderId}")
```

이번 과제에서는 주문 레코드를 실제로 삭제하지 않고 `deleted = true`로 변경하는 Soft Delete에 사용했다.

---

### `@RequestBody`

클라이언트가 HTTP 요청 Body에 보낸 JSON 데이터를 Java DTO 객체로 변환한다.

```java
public ResponseEntity<OrderResponseDto> createOrder(
        @RequestBody OrderCreateRequestDto dto
) {
}
```

예를 들어 다음 JSON은 `OrderCreateRequestDto`로 변환된다.

```json
{
  "buyerId": 961,
  "recipient": "예은",
  "phoneNumber": "010-1234-5678"
}
```

---

### `@PathVariable`

URL 경로에 포함된 값을 메서드의 매개변수로 전달한다.

```java
@GetMapping("/{orderId}")
public ResponseEntity<OrderResponseDto> getOrderById(
        @PathVariable Long orderId
) {
}
```

`GET /orders/1` 요청을 보내면 `orderId`에 `1`이 전달된다.

---

## 2. Spring 및 트랜잭션 어노테이션

### `@Service`

클래스를 비즈니스 로직을 담당하는 서비스로 등록한다. Spring이 해당 객체를 생성하고 관리한다.

```java
@Service
public class OrderService {
}
```

이번 과제의 `OrderService`에서는 다음 작업을 처리했다.

- 구매자와 상품 조회
- 주문 생성
- 주문 목록 및 상세 조회
- 배송정보 수정
- 배송 상태 확인
- Soft Delete

---

### `@Transactional`

메서드 안에서 실행되는 여러 DB 작업을 하나의 작업 단위로 처리한다.

```java
@Transactional
public OrderResponseDto updateOrder(...) {
}
```

트랜잭션이 정상적으로 끝나면 작업을 커밋하고, 실행 중 예외가 발생하면 변경 내용을 롤백할 수 있다.

JPA가 관리하는 엔티티는 `@Transactional` 내부에서 값을 변경하면 별도의 `save()` 호출 없이도 변경 감지(Dirty Checking)를 통해 DB에 반영된다.

```java
order.updateShippingAddress(dto.toShippingAddress());
```

Soft Delete도 같은 방식으로 처리했다.

```java
order.softDelete();
```

---

### `@Transactional(readOnly = true)`

해당 트랜잭션이 데이터를 변경하지 않고 조회만 수행한다는 의미다.

```java
@Transactional(readOnly = true)
public OrderResponseDto getOrderById(Long orderId) {
}
```

조회 메서드의 목적을 명확하게 표현하고, JPA의 불필요한 변경 감지 부담을 줄이는 데 도움을 준다.

---

## 3. JPA 어노테이션

### `@Entity`

클래스를 JPA가 관리하는 엔티티로 등록한다. 일반적으로 데이터베이스 테이블과 매핑된다.

```java
@Entity
public class Orders {
}
```

---

### `@Id`

엔티티의 기본 키(Primary Key)를 지정한다.

```java
@Id
private Long id;
```

---

### `@GeneratedValue`

기본 키 값을 자동으로 생성하도록 설정한다.

```java
@GeneratedValue(strategy = GenerationType.IDENTITY)
```

`IDENTITY` 전략은 데이터베이스의 자동 증가 기능을 이용한다.

---

### `@Column`

엔티티 필드와 매핑되는 DB 컬럼의 속성을 설정한다.

```java
@Column(nullable = false)
private Boolean deleted;
```

`nullable = false`는 해당 컬럼에 `null` 값을 허용하지 않는다는 뜻이다.

---

### `@Enumerated`

Java Enum 값을 데이터베이스에 저장하는 방식을 설정한다.

```java
@Enumerated(EnumType.STRING)
private DeliverStatus deliverStatus;
```

`EnumType.STRING`을 사용하면 다음 값이 문자열로 저장된다.

```text
PREPARATION
DEPARTURE
COMPLETED
```

Enum의 순서 번호를 저장하는 `ORDINAL` 방식보다 의미를 파악하기 쉽고, Enum 순서가 변경돼도 기존 데이터가 잘못 해석될 위험이 적다.

---

### `@Embeddable`

해당 클래스가 다른 엔티티 내부에 포함될 수 있는 값 객체임을 나타낸다.

```java
@Embeddable
public class ShippingAddress {
}
```

`ShippingAddress`는 독립적인 엔티티가 아니라 주문에 포함되는 배송정보 값 객체다. 따라서 별도의 ID를 가지지 않는다.

---

### `@Embedded`

`@Embeddable`이 붙은 값 객체를 엔티티에 포함한다.

```java
@Embedded
private ShippingAddress shippingAddress;
```

별도의 배송정보 테이블을 생성하지 않고 `ShippingAddress`의 필드들이 `orders` 테이블의 컬럼으로 저장된다.

```text
recipient
phone_number
road_address
detail_address
zip_code
```

---

### `@ManyToOne`

여러 엔티티가 하나의 엔티티를 참조하는 다대일 관계를 표현한다.

```java
@ManyToOne
@JoinColumn(name = "buyer_id")
private Member buyer;
```

여러 주문이 한 명의 구매자를 참조할 수 있으므로 `Orders`와 `Member`를 다대일 관계로 연결했다.

---

### `@OneToMany`

하나의 엔티티가 여러 엔티티를 가지는 일대다 관계를 표현한다.

```java
@OneToMany(
        mappedBy = "orders",
        cascade = CascadeType.ALL
)
private List<ProductOrders> productOrders;
```

하나의 주문에는 여러 상품이 포함될 수 있으므로 `Orders`와 `ProductOrders`를 일대다 관계로 연결했다.

`mappedBy = "orders"`는 연관관계의 주인이 `ProductOrders.orders` 필드라는 뜻이다.

---

### `@OneToOne`

두 엔티티가 일대일 관계임을 표현한다.

```java
@OneToOne(mappedBy = "orders", cascade = CascadeType.ALL)
private Coupon coupon;
```

---

### `@JoinColumn`

연관관계에서 사용할 외래 키 컬럼의 이름을 지정한다.

```java
@JoinColumn(name = "buyer_id")
```

`orders` 테이블의 `buyer_id`가 `member` 테이블의 회원을 참조한다.

---

### `cascade = CascadeType.ALL`

부모 엔티티에 수행한 영속성 작업을 연관된 자식 엔티티에도 전파한다.

```java
@OneToMany(
        mappedBy = "orders",
        cascade = CascadeType.ALL
)
```

이번 과제에서는 `Orders`를 저장할 때 연결된 `ProductOrders`도 함께 저장되도록 사용했다.

---

## 4. Lombok 어노테이션

### `@Getter`

필드 값을 조회하는 getter 메서드를 자동 생성한다.

```java
@Getter
public class OrderResponseDto {
}
```

---

### `@Builder`

빌더 패턴을 이용해 객체를 생성할 수 있게 한다.

```java
Orders order = Orders.builder()
        .buyer(buyer)
        .deliverStatus(DeliverStatus.PREPARATION)
        .shippingAddress(shippingAddress)
        .build();
```

생성자 매개변수의 순서를 기억하지 않아도 되고, 어떤 필드에 어떤 값을 넣는지 명확하게 확인할 수 있다.

---

### `@Builder.Default`

Lombok 빌더로 객체를 생성할 때도 필드의 기본값이 유지되도록 한다.

```java
@Builder.Default
private List<ProductOrders> productOrders = new ArrayList<>();
```

```java
@Builder.Default
private Boolean deleted = false;
```

`productOrders`를 빈 리스트로 초기화해 `NullPointerException`을 방지하고, 새로운 주문의 삭제 여부가 기본적으로 `false`가 되도록 사용했다.

---

### `@RequiredArgsConstructor`

`final` 필드를 매개변수로 받는 생성자를 자동 생성한다.

```java
@RequiredArgsConstructor
public class OrderService {
    private final OrderRepository orderRepository;
}
```

이를 통해 생성자 코드를 직접 작성하지 않고 생성자 주입을 사용할 수 있다.

---

### `@NoArgsConstructor`

매개변수가 없는 기본 생성자를 자동 생성한다.

```java
@NoArgsConstructor
public class Orders {
}
```

JPA가 엔티티를 조회한 뒤 객체를 생성할 때 기본 생성자가 필요하다.

---

### `@AllArgsConstructor`

모든 필드를 매개변수로 받는 생성자를 자동 생성한다.

```java
@AllArgsConstructor
public class Orders {
}
```

---

## 5. 테스트 어노테이션

### `@ExtendWith(MockitoExtension.class)`

JUnit 테스트에서 Mockito 기능을 사용할 수 있도록 확장 기능을 등록한다.

```java
@ExtendWith(MockitoExtension.class)
class ProductServiceTest {
}
```

---

### `@Mock`

실제 객체 대신 사용할 가짜 Mock 객체를 생성한다.

```java
@Mock
private ProductRepository productRepository;
```

실제 DB에 연결하지 않고 Repository의 동작을 직접 지정하여 Service를 테스트할 수 있다.

---

### `@InjectMocks`

테스트 대상 객체를 생성하고 `@Mock`으로 만든 객체들을 주입한다.

```java
@InjectMocks
private ProductService productService;
```

---

### `@Test`

해당 메서드를 JUnit 테스트 메서드로 지정한다.

```java
@Test
void createProductSuccess() {
}
```

---

### `@DisplayName`

테스트 결과 화면에 표시할 설명을 지정한다.

```java
@DisplayName("판매자는 상품을 성공적으로 등록할 수 있다.")
```

메서드 이름 대신 사람이 이해하기 쉬운 한글 테스트 설명을 표시할 수 있다.

---

## 6. 핵심 정리

| 분류 | 어노테이션 | 역할 |
|---|---|---|
| Web | `@RestController` | HTTP 요청을 처리하는 컨트롤러 등록 |
| Web | `@RequestMapping` | 공통 URL 지정 |
| Web | `@PostMapping` | 생성 요청 처리 |
| Web | `@GetMapping` | 조회 요청 처리 |
| Web | `@PutMapping` | 수정 요청 처리 |
| Web | `@DeleteMapping` | 삭제 요청 처리 |
| Web | `@RequestBody` | JSON을 DTO로 변환 |
| Web | `@PathVariable` | URL 경로 값을 매개변수로 전달 |
| Spring | `@Service` | 서비스 Bean 등록 |
| Transaction | `@Transactional` | 트랜잭션 및 변경 감지 적용 |
| JPA | `@Entity` | JPA 엔티티 등록 |
| JPA | `@Id` | 기본 키 지정 |
| JPA | `@GeneratedValue` | 기본 키 자동 생성 |
| JPA | `@Enumerated` | Enum 저장 방식 지정 |
| JPA | `@Embeddable` | 포함 가능한 값 객체 선언 |
| JPA | `@Embedded` | 값 객체를 엔티티에 포함 |
| JPA | `@ManyToOne` | 다대일 관계 설정 |
| JPA | `@OneToMany` | 일대다 관계 설정 |
| JPA | `@OneToOne` | 일대일 관계 설정 |
| JPA | `@JoinColumn` | 외래 키 컬럼 지정 |
| Lombok | `@Getter` | getter 자동 생성 |
| Lombok | `@Builder` | 빌더 자동 생성 |
| Lombok | `@Builder.Default` | 빌더에서도 기본값 유지 |
| Lombok | `@RequiredArgsConstructor` | `final` 필드 생성자 생성 |
| Lombok | `@NoArgsConstructor` | 기본 생성자 생성 |
| Lombok | `@AllArgsConstructor` | 전체 필드 생성자 생성 |
| Test | `@ExtendWith` | JUnit 확장 기능 등록 |
| Test | `@Mock` | 가짜 객체 생성 |
| Test | `@InjectMocks` | Mock을 테스트 대상에 주입 |
| Test | `@Test` | 테스트 메서드 지정 |
| Test | `@DisplayName` | 테스트 이름 지정 |
